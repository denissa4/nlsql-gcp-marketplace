NLSQL {{ .Chart.AppVersion }} is installing into namespace "{{ .Release.Namespace }}"
as release "{{ .Release.Name }}".

1. Wait for the pods to become ready:

     kubectl wait --namespace {{ .Release.Namespace }} \
       --for=condition=available --timeout=300s \
       deployment/{{ include "nlsql.fullname" . }}

2. Confirm the app is healthy:

     kubectl port-forward --namespace {{ .Release.Namespace }} \
       svc/{{ include "nlsql.fullname" . }} 8080:{{ .Values.service.port }}
     curl http://localhost:8080/health

{{- if .Values.ingress.enabled }}

3. Your Ingress is provisioning a Google Cloud load balancer. This takes a few
   minutes. Watch for an external address:

     kubectl get ingress --namespace {{ .Release.Namespace }} \
       {{ include "nlsql.fullname" . }} --watch

   Reachable at:
{{- range .Values.ingress.hosts }}
{{- range .paths }}
     http{{ if $.Values.ingress.tls }}s{{ end }}://{{ .host | default "<ingress-address>" }}{{ .path }}
{{- end }}
{{- end }}
{{- else }}

3. NLSQL is not exposed outside the cluster. To publish it, set `ingress.enabled=true`
   with a hostname - see "Expose the application" in the deployment documentation:
   https://github.com/denissa4/nlsql-gcp-marketplace/blob/main/README.md
{{- end }}

4. View the app in the Google Cloud console:

     https://console.cloud.google.com/kubernetes/application/_/_/{{ .Release.Namespace }}/{{ .Release.Name }}
