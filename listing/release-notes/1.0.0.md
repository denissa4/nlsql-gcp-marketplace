Version title: 1.0.0 - First release on Amazon ECS

Release notes:

Critical
- None. This is the first release of NLSQL AI Agent on AWS Marketplace; there is nothing to upgrade from.

Important
- Deploys on Amazon ECS with AWS Fargate from an AWS CloudFormation template: one task, an Application Load Balancer that only accepts requests from the stack's own CloudFront distribution, and an HTTPS messaging endpoint for Microsoft Teams.
- Two modes: DocsAndSql (default) answers from your documents and, through NLSQL, from your SQL database (SQL Server, MySQL, PostgreSQL, Amazon Redshift, Snowflake) with charts and tables; DocsOnly answers from documents alone.
- Answers are generated by Claude on Amazon Bedrock through global inference profiles, called with the ECS task role. No AWS access keys are needed, and static AWS credential variables are ignored on ECS. Choose Claude Opus 5 (default), Opus 5.5, Opus 4.8, Sonnet 5, Sonnet 5.5, Sonnet 4.6 or Haiku 4.5. Each model must be enabled in Amazon Bedrock in your account before use.
- Documents are read from a private, encrypted Amazon S3 bucket the stack creates (or one you name) and indexed at start-up. Supported formats: PDF, Word (.docx, tables included), Excel (.xlsx, all worksheets; not the older .xls), OpenDocument (.odt, .ods) and text files (.txt, .csv, .md, .json, .jsonl, .html, .htm). A document that cannot be read is skipped, and the log names it. The embedding model is part of the image, so no model is downloaded at run time. After adding documents, start a new deployment of the service to re-index; /ready reports when indexing has finished, which can be after the deployment completes.
- Teams turns are acknowledged immediately and answered as soon as they are ready, so long questions are not cut off by Teams' time limits. In DocsAndSql mode, a data question NLSQL has not answered within 330 seconds gets "Your data question is taking longer than expected. Please try again in a few minutes." instead of an answer from the documents.
- Files sent to the bot in a personal chat, in the formats above, are answered from directly. A file the bot cannot read gets a reply that says so and lists the supported formats. Pasted images and screenshots are not read: in DocsAndSql mode such a message goes to NLSQL first, like any other.
- The messaging endpoint accepts requests only from the Microsoft Bot Connector (Teams, and Test in Web Chat in the Azure portal) and from the bot's own app registration. Any other app in your Microsoft Entra tenant gets 401.
- Credentials (bot client secret, NLSQL API token, database password) are read from one AWS Secrets Manager secret, optionally encrypted with your own AWS KMS key, and are never written to the task definition or the logs.
- The container runs as a non-root user on port 8080, on a supported Debian 13 and Python 3.13 base. The subscription is verified with the AWS Marketplace Metering Service before the task serves any request: the bot, NLSQL and the document service each check the signed result, and /health returns 503 until then.
- Charts and CSV exports are served from unguessable links and deleted after 24 hours.

Optional
- LanguageModelContext sets your own system prompt for document answers.
- Streaming shows document answers in Teams as they are generated.
- TaskCpu, TaskMemory and EphemeralStorage size the task; the defaults (4 vCPU, 8 GB, 40 GiB) suit most document sets.
