Version title: 1.0.0 - First release on Amazon ECS

Release notes:

Critical
- None. This is the first release of NLSQL AI Employee on AWS Marketplace; there is nothing to upgrade from.

Important
- Deploys on Amazon ECS with AWS Fargate from an AWS CloudFormation template: one task, an Application Load Balancer that only accepts requests from the stack's own CloudFront distribution, and an HTTPS endpoint for your Azure Bot's messaging endpoint and the Microsoft 365 sign-in.
- Microsoft 365 in Microsoft Teams: after typing login once, each user's mail, calendar and OneDrive files are reached through Microsoft Graph with that user's own delegated sign-in. The refresh tokens are stored in your DynamoDB table, encrypted with a key the stack generates in AWS Secrets Manager.
- Scheduling and memory: /schedule sets one-off and recurring tasks in plain language, /briefing a daily morning briefing, and /watch alerts for important email (with draft replies) and meeting-prep briefs about 15 minutes ahead. /tasks lists them and /memory shows what the assistant was asked to remember. Times are UTC. Results arrive as messages in the user's chat.
- Answers are generated by Claude on Amazon Bedrock through global inference profiles, called with the ECS task role. No AWS access keys are needed, and static AWS credential variables are ignored on ECS. Choose Claude Sonnet 5.5 (default), Opus 5, Opus 5.5, Opus 4.8, Sonnet 5, Sonnet 4.6 or Haiku 4.5. Each model must be enabled in Amazon Bedrock in your account before use.
- Every Azure Bot Service channel you enable is served. Microsoft 365 features are available in Teams only; Web Chat, Direct Line, Telegram and the other channels work without them. A user ID belongs to the first channel that used it, so another channel cannot read that user's data by sending the same ID.
- Turns are acknowledged immediately and answered as soon as they are ready, so long agent runs are not cut off by Bot Framework's time limits.
- Files sent to the bot in a personal chat (up to 50 MiB) are read: PDF, Word (.docx), Excel (.xlsx, the active sheet), OpenDocument (.odt, .ods) and UTF-8 text files. They stay on the task's disk for at most 24 hours untouched and, for a signed-in Teams user, are also copied to their OneDrive folder AI Employee Uploads.
- The messaging endpoint accepts requests only from the Microsoft Bot Connector and from the bot's own app registration. Any other app in your Microsoft Entra tenant gets 401.
- Users' sign-ins, scheduled tasks, conversation history, memory and files are kept in two Amazon DynamoDB tables and two Amazon S3 buckets the stack creates. They are kept when the stack is deleted, so an upgrade keeps users signed in with their history and tasks.
- The bot's client secret (and the optional Gemini key) are read from one AWS Secrets Manager secret, optionally encrypted with your own AWS KMS key. The keys used inside the task are generated, never typed in. No secret is written to the task definition or the logs, and logs carry no query strings or conversation content.
- The container runs as a non-root user on port 8080, on a supported Debian 13, Python 3.13 and Node.js 24 base. The subscription is verified with the AWS Marketplace Metering Service before the task serves any request, and /health returns 503 until then.
- Only the product's own paths are public: the messaging endpoint, the sign-in callback, /health, the chat cards' images and, with Gemini, the live browser view. Everything else gets 403.

Optional
- GeminiFeatures, with your own Google Gemini API key: a browser agent that browses the web for the user, and image reading. Off by default; without a key these features are not offered and nothing is sent to Google. The live browser can be watched and taken over: in Teams from an Open live browser button that opens a Teams dialog, elsewhere from a signed link. There is no network-reachable VNC service; viewer access requires a signed per-session token. The browser runs under a locked-down managed policy and without Chromium's sandbox, which AWS Fargate cannot provide.
- AdditionalInstructions adds your own instructions to the built-in system prompt.
- Streaming shows answers in the chat as they are generated.
- ConversationMemoryTokens sets how much of each conversation the model sees; older messages are summarized.
- TaskCpu, TaskMemory and EphemeralStorage size the task; the defaults (2 vCPU, 8 GB, 40 GiB) run 4 live browsers at once.

Known limitations
- Code mode (the coder service) is not part of 1.0.0.
- In Teams the app is installed in personal scope only, not in channels or group chats.
- A live-browser link sent outside Teams is valid for about an hour and works as a bearer credential; it is sent only into the user's own conversation.
- The service runs exactly one task: a deployment interrupts conversations in progress and ends live browser sessions.
