Version title: 1.0.1 - Clear replies when the model fails; streaming only where answers are edited

Release notes:

Critical
- None.

Important
- When a turn's call to Amazon Bedrock fails, the user now gets a reply that says so, with the AWS error code: that access to the model was denied (enable the model in Amazon Bedrock for the account, and check that the task role may invoke it), that the model is busy, or that another error occurred. The log group gets one line, NLSQL AI Employee: an answer failed (<ErrorCode>). In 1.0.0 the chat showed only "No response from server." and nothing was logged. When the failure comes after a tool already ran (an email sent, an event created), the reply asks to check its results rather than to try again.
- An answer the model returns without any text, for example one its content filter stopped, is explained the same way, and /schedule then says to check /tasks.
- Streaming applies only where the bot edits an answer in place: Microsoft Teams and Telegram. Web Chat, Direct Line and the other channels now get each answer in one message; with Streaming=true they used to get a "Thinking..." card that never changed and one message per streamed chunk.
- To upgrade, update the stack with this version's template, whose ImageUri default is the 1.0.1 image. The tables, buckets and secrets are kept, so users stay signed in with their history and tasks.

Known limitations
- Code mode (the coder service) is not part of 1.0.1.
- In Teams the app is installed in personal scope only, not in channels or group chats.
- A live-browser link sent outside Teams is valid for about an hour and works as a bearer credential; it is sent only into the user's own conversation.
- The service runs exactly one task: a deployment interrupts conversations in progress and ends live browser sessions.
